# UI Internationalization

The web UI is translated with GNU gettext catalogs loaded through
[`gotext`](https://github.com/leonelquinteros/gotext). English is the source
language and the final fallback.

The translation machinery is in place, but no string is marked for
translation yet and only `en` is enabled. This page describes how it works
and the steps to enable and ship the first translation.

## How it works

- Templates call `{{.L.T "English text"}}` or
  `{{.L.N "singular" "plural" .Count}}`. The English text is the gettext
  `msgid`, so English needs no catalog. Go code in `auth` and
  `server/ui/web` calls the same `T` and `N` methods on a `Printer`.
- `go run ./internal/tools/i18nscan` finds those calls in the templates and
  the Go code and writes the template `server/ui/i18n/po/ui.pot` itself.
  `#:` references point at the templates and Go sources. With no marked
  strings the POT holds only its header.
- `msgmerge` updates each `po/<lang>.po` from the template. Translators edit
  the `.po` files.
- `msgfmt` compiles each `.po` into
  `locale/<lang>/LC_MESSAGES/ui.mo`. Only `locale/` is embedded in the
  binary.
- Supported languages are listed in `server/ui/i18n/LINGUAS`. Each needs an
  entry in `languageInfo` (`server/ui/i18n/languages.go`) with its own name
  and text direction.
- Page contexts expose the request's `Printer` as `.L`. It also formats
  dates and numbers for the locale.

### Which language a request gets

1. The language stored for the signed-in user (`users.locale`), when it is a
   supported tag.
2. Otherwise the best match for the `Accept-Language` header.
3. Otherwise `en`.

An empty stored value skips step 1. Without a session (for example the login
page, or noauth mode) only steps 2 and 3 apply. Nothing in the UI writes the
stored value yet, so until a language selector exists the header decides.

## Prerequisites

- Go: `make i18n-extract` runs `i18nscan`, which needs no other tools.
- GNU gettext 1.0 or later, needed once a language is enabled:
  `brew install gettext` on macOS (keg-only, add its `bin` to `PATH`),
  `sudo apt-get install gettext` on Debian and Ubuntu. The tools used are
  `msginit`, `msgmerge`, `msgfmt` and `msgattrib`. Older `msgmerge` drops the
  `#, go-format` flags.

## Enable and ship the first translation

The steps below take the first language, here `it`, from nothing to
released. Do them as separate commits so each can be reviewed alone.

1. **Mark strings.** Wrap the text in a template: `{{.L.T "Save changes"}}`.
   Use `fmt` verbs for arguments (`{{.L.T "Delete device %s?" .Name}}`). In
   plurals the count is argument 1, so write `%[1]s device` and number other
   arguments from `%[2]s`. Only direct `.T(` and `.N(` calls are extracted;
   method values and aliases such as `$l := .L` are not. Mark a page at a
   time and keep the English output unchanged.
2. **Extract.** `make i18n-extract` regenerates `po/ui.pot`. Review it:
   every marked string should appear once, with its `#:` references.
3. **Create the catalog.**

   ```sh
   msginit --no-translator --input=server/ui/i18n/po/ui.pot \
     --locale=it --output-file=server/ui/i18n/po/it.po
   ```

   Check that `Plural-Forms` in the `.po` header is right for the language.
4. **Enable the language.** Add `it` to `server/ui/i18n/LINGUAS` after `en`
   and make sure `languageInfo` has an entry for it.
5. **Translate.** Fill in the empty `msgstr` entries in `po/it.po`. A `fuzzy`
   flag from `msgmerge` means a guessed translation: fix it and remove the
   flag.
6. **Compile.** `make i18n-compile` writes
   `locale/it/LC_MESSAGES/ui.mo`. Commit the `.mo`: it is what the binary
   embeds.
7. **Point the catalog probe at a real string.** `probeKey` in
   `server/ui/i18n/catalog.go` must be a marked message that every non-English
   catalog translates. Startup logs an error and serves English for a
   catalog that does not translate it.
8. **Drop the test scaffolding.** While `locale/` is empty, the `i18n` tests
   run against a fixture:
   - `server/ui/i18n/main_test.go` overrides `supported`, `matcher` and
     `printers`. Delete it.
   - `server/ui/i18n/testdata/` holds the fixture `it.po` and `ui.mo`.
     Delete it, then point `TestLoadPrintersPassesFixtureCatalog` and
     `TestFixtureCatalogMatchesPo` back at `catalogFS` and `po/it.po`.
   - `server/ui/i18n/locale/.gitkeep` is no longer needed.
   - `TestBasePrinterLocale` in `server/ui/web/pagebuilder_test.go` can gain
     cases that resolve to `it`.
9. **Let users pick the language.** Add a selector that calls
   `User.SetLocale` and a handler for it. Until then only `Accept-Language`
   selects a non-English UI.
10. **Check.** `make i18n-check`, then commit the `.pot`, `.po` and `.mo`
    files.
11. **Open the PR.** The `i18n` workflow runs `make i18n-check` and the
    xgettext cross-check. It must be green before merge.

### Try it locally

```sh
./contrib/run-local.sh          # login: admin / admin
curl -s -H 'Accept-Language: it' http://localhost:8080/login | grep '<html'
```

Template and catalog changes need a rebuild. `air` (see
`docs/run-locally.md`) does this on `*.go`, `*.html` and `*.css` changes;
`.mo` files are embedded, so run `make i18n-compile` and let `air` rebuild.

## Change or add a message

1. Mark or edit the text as in step 1 above.
2. `make i18n-extract` regenerates `po/ui.pot`.
3. `make i18n-merge` adds the new entries to every `po/<lang>.po`.
4. Translate the empty and fuzzy entries.
5. `make i18n-compile` rebuilds the `.mo` files.
6. `make i18n-check`, then commit the `.pot`, `.po` and `.mo` files.

A copy edit to the English text changes the `msgid`, so the translation is
lost until it is redone. `msgmerge` may keep the old one as `fuzzy`.

## Add another language

Repeat steps 3 to 6 and 10 above with the new tag. Add it to `LINGUAS` in
alphabetical order after `en`.

## Checks

`make i18n-check` runs extract, merge and compile, then fails when:

- a file under `server/ui/i18n` differs from the regenerated one, so run it
  after committing or staging nothing else in that directory;
- a `.po` has untranslated or fuzzy entries (`msgattrib`);
- the i18n Go tests fail.

`make i18n-extract` writes the POT with `i18nscan`. To write it with GNU
`xgettext` 1.0 instead, run `make i18n-extract I18N_EXTRACTOR=xgettext`. The
output is identical, and CI checks that. Use it if the native writer breaks
on a construct `xgettext` handles. It does not support translator comments.

Obsolete `#~` entries are kept by `msgmerge` and are not checked. Remove them
by hand.

A missing translation is not a runtime error: `Get` returns the English text.
Detection happens at build time only.
